# CRDT 7,076 Sample

## Deployed demo

Open the deployed App with:

```text
/?fileId=crdt-7076-sample
```

The deployed demo is a single-client document preview. It still calls the
formal same-origin document database API. When that database is unavailable,
the App reports that persistence is unavailable and loads
`document.json.gz`, the checked-in compressed canonical 7,076-element result.
The Canvas remains usable. No Collaboration server, CRDT session, fake
persistence provider, IndexedDB fallback, or localStorage fallback is composed.

`document.json.gz` is generated by
`yarn workspace @asyra/asyra-design generate:crdt-7076-document`. The generator
executes the ordinary prepared action and Factory transaction, saves the
resulting canonical document, verifies the 7,076-element count, and compresses
that JSON for static delivery. Core remains the schema and canonical validation
owner when the App loads it.

## Full local Agent and CRDT flow

Start the App through the repository's local development workflow. Start the
reference WebSocket server separately with the App workspace
`collaboration:server` command; root `dev:all` does not start it. Configure
`VITE_COLLABORATION_WS_URL`, then open two App windows with:

```text
http://localhost:3000/?fileId=crdt-7076-sample
```

In Actor A:

1. Open the Agent panel.
2. Attach `reference-image.png`.
3. Paste the complete contents of `instruction.txt`.
4. Press Send.

Opening the URL alone does not create anything. The ordinary Agent request sends
the image and instruction to the same-origin action-batch backend. After the
backend matches both exact inputs, it reads `converted-vector-data.svg` and
returns one prepared `AiActionBatch`.

The checked-in conversion contains 7,075 editable Vector children. The ordinary
App action creates one Group around those children, so Actor A and Actor B each
finish with 7,076 canonical elements.

This sample request does not run VTracer or another image converter. Actor A
executes, renders, publishes, and persists through the ordinary product owners.
Actor B receives and renders the drawing only through CRDT. Actor B creates no
Undo, echo publication, or persistence save; `peer-applied` acknowledges its
completed canonical apply rather than durability.

The repository intentionally defines only the frontend document-database
contract. Without a matching `/api/documents/<encoded fileId>` server, local
persistence reports unavailable while the App and CRDT session continue. An
App fork supplies that server to enable durable reloads without changing the
frontend persistence composition.
