# Asyra v0.5.0

## Build product features, not infrastructure

Asyra v0.5.0 is the first release to bring the framework, the maintained
Asyra Design product, public documentation, and release tooling together as one
cohesive product-infrastructure stack.

Apps keep ownership of their schemas, rules, workflows, services, and UI.
Asyra supplies the repeatable boundaries around them: intent routing,
registration, transactions, rollback, Undo/Redo, validation, canonical state,
rendering projections, persistence, collaboration, and optional AI execution.

This release advances the project from the `v0.2.5` GitHub baseline to the
current `0.5.x` package family. Individual `@asyra/*` packages use independent
patch versions within that family; the exact published versions are recorded
in their package manifests and release artifacts.

## Highlights

### One explicit owner for product behavior

- App-owned Features are now the primary runtime path for human, UI,
  automation, device, and AI intent.
- Features declare priority, exclusivity, execution, and session behavior at
  one product boundary instead of duplicating handlers for each caller.
- `@asyra/core` exposes curated public composition APIs while component,
  property, selection, render, and transaction owners retain their focused
  responsibilities.
- The former interaction-core path has been retired. Input events now enter
  the Feature System through the supported runtime flow.

### Transaction-safe canonical state

- Local application transactions provide commit, rollback, cancellation, and
  cleanup as one lifecycle.
- One intended user action can produce one intended Undo entry, including
  continuous canvas gestures.
- Property updates, component changes, hierarchy operations, and remote
  changes converge on canonical owner paths rather than parallel UI state.
- Selection is channel-based and supports element, vector-point, and
  vector-segment ownership with deterministic replay behavior.

### Replaceable rendering and explicit presets

- Rendering is separated into stable render orchestration, a renderer-neutral
  engine contract, and the Pixi implementation.
- Apps can register custom render strategies and layers without importing
  Pixi classes through the public render surface.
- Preset composition is explicit at startup. Apps can select, extend, replace,
  query, and clean up stable preset targets without depending on private
  framework internals.
- Render updates consume committed deltas so an unchanged element does not
  require complete scene reconstruction.

### A complete Asyra Design reference product

- The maintained design App demonstrates editable vector information, Pen and
  path editing, fills and gradients, selection and hover, property editing,
  Groups, Layers hierarchy, Undo/Redo, and registered rendering overlays.
- Group, Ungroup, nested hierarchy, reparenting, reordering, subtree deletion,
  and restore flows preserve canonical identity and transaction boundaries.
- The 7,076-element reference sample contains one App-owned Group and 7,075
  editable Vectors, exercising the ordinary Agent, Runtime, canonical-state,
  Render, Undo/Redo, persistence, and collaboration paths.
- Whole-element vector movement updates local geometry without rewriting every
  point, and child edits remain independent of the size of an ancestor Group.

### Optional collaboration with durable recovery

- `@asyra/collaboration` provides optional Yjs-backed live publication
  transport without making collaboration a Core dependency.
- Publications carry accepted canonical changes; private History, Selection,
  Awareness, Render, and UI state stay outside the shared payload.
- Asyra Design provides a production-shaped socket document session with
  checkpoint-plus-tail bootstrap, server sequencing, peer fan-out, and backend
  materialization.
- An App-owned IndexedDB outbox retains unaccepted local publications through
  connection loss. Editing remains available while transport reconnects, and
  transport acceptance remains distinct from backend durability.
- The two-client 7,076-element sample demonstrates an Agent-created canonical
  result converging through CRDT to a second live client.

### Optional AI actions through the same product boundaries

- `@asyra/ai-agent-runtime` adds optional provider-neutral orchestration and
  operational progress observation.
- AI actions enter registered App Features and use the same validation,
  transactions, rollback, canonical state, History, rendering, persistence,
  and collaboration paths as other callers.
- Asyra Design includes a conversational drawing reference flow, recoverable
  partial results, explicit confirmation and progress UI, and server-owned
  model credentials.
- Runtime progress exposes operational phases and concise explanations, never
  private model reasoning.

### Public packages, starter, and documentation

- Asyra now publishes 19 public ESM `@asyra/*` packages with TypeScript
  declarations and package-owned public entrypoints.
- `@asyra/core` is the package-first composition facade for the supported
  browser/Core runtime.
- `create-asyra-design-app` generates an ordinary, editable Asyra Design
  codebase for Yarn, npm, or pnpm consumers.
- Public documentation now covers composition, information models, custom
  schemas, transaction-safe Features, runtime boundaries, support policy, and
  the complete Asyra Design case study.
- Release automation validates workspace dependency ranges, clean package
  artifacts, generated starter output, and exact local-tarball consumer
  installation before publication.

### Flow Inspector 0.2.0

- Inspector artifacts now live under one tool-owned registry while their
  product and architecture contracts remain owned by the relevant Framework
  or App scope.
- The static React workspace provides search, grouping, stable routes, target
  isolation, zoom, scrolling, panel controls, and complete contract details for
  32 current-project Inspectors.
- Runtime execution status, CI enforcement, commands, and integrations remain
  intentionally deferred; this release is a contract-reading and navigation
  tool, not a control plane.

## Upgrade notes

### Node.js 24 is required

Node.js `24.x` is the supported runtime for repository development, package
verification, generated consumers, and release automation. Node.js 20 is no
longer a supported path. The repository continues to use Yarn `4.3.1`.

### Apply presets explicitly

Framework defaults no longer appear through hidden startup side effects.
Applications must apply their selected preset during startup and keep the
returned application lifetime for cleanup. Use public preset targets and Core
delegates instead of importing preset or runtime internals.

### Use the public Core and render-engine boundaries

- Import supported composition APIs from `@asyra/core`.
- Do not depend on the retired interaction-core runtime path.
- Do not import Pixi classes from `@asyra/render`; select or implement a render
  engine through the public engine contract.
- Use shared-channel import/get APIs rather than accessing Yjs instances
  directly.

### Keep persistence policy outside Core

Core owns validated load/apply and explicit serialization boundaries, not an
automatic application durability policy. Apps and their backends own transport,
retry, sequencing, checkpoint, and durability decisions. The Asyra Design
socket flow is a maintained reference implementation, not a mandatory service
for every Asyra App.

### Rename fork-facing runtime configuration

Asyra Design uses brand-neutral runtime identifiers such as
`AI_PROVIDER_ENDPOINT`, `AI_PROVIDER_MODEL`, `AI_PROVIDER_API_KEY`, and
`DOCUMENT_BACKEND_DATA_DIR`. Branded compatibility aliases are not retained.
Existing backend data is not automatically discovered under renamed defaults;
set `DOCUMENT_BACKEND_DATA_DIR` to the existing location when migration is
required.

## Current support boundary

This release supports the browser/Core composition, the official `2D` Preset,
engine-neutral `CUSTOM` composition, public ESM entrypoints with TypeScript
declarations, and Node.js 24 package verification.

Production `3D`, `HYBRID`, auto-layout, unit-aware aggregation, public Headless
Core, and a multi-runtime Core Kernel are not included in this release.

## Get started

Install the package-first composition facade:

```bash
npm install @asyra/core
```

Or create the complete design-product reference:

```bash
npx create-asyra-design-app my-product --package-manager=npm
cd my-product
npm run start
```
